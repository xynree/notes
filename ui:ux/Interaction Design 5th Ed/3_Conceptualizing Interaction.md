# 3 - Conceptualizing Interaction

## 3.1 - Introduction

- Ideas in a design project should be conceptualized in terms of whta the product will do ("Proof of concept")
- Reality check: Assumptions are scrutinized in terms of feasibility
- Actual problems should be identified "It is difficult to do X"

## 3.2 - Conceptualizing Interaction

- Be clear about underlying assumptions: Writing down assumptions and trying to defend/support them help identify vague assumptions
- Are there problems with the existing product/UX?
- Why do you think there are problems?
- What evidence to support the existence of these problems?
- How do you think your proposed design ideas will overcome those problems?

- Conceptualize the design space provides benefits: Orientation, Open-mindedness, common ground
  - Conceptual model becomes a shared blueprint for a testable proof of concept

## 3.3 Conceptual Models

- Simplified description of a system/process to help describe how it works
- Working strategy and framework of general concepts and relations
- What's in a conceptual model?
  - Metaphors and analogies that ocnvery to people how to understand what a product is used for
  - Concept sto which people are exposed through the product
  - Relationships between those concepts
  - Mappings between concepts and UX the product is designed to support or invoke
- "Design Concept": Set of ideas for the design. Scenarios, images, mood boards or text-based documents.
- Most applications are based on well-established conceptual models

## 3.4 - Interface Metaphors

- Provide familiar entities that enable people to understand the underlying conceptual model and know what to do at the interface
- Can sometimes contradict user's mental models: Example: Recycle bin on desktop
- Interface metaphor: Card
  - Operate similar to real world card - lightweight "paperbased" type of movemnet.

## 3.5 - Interaction Types

- Can conceptualized design space in terms of interaction types underlying the user experience
  - Instructing, conversing, manipulating, exploring, responding
    - Responding: Proactive situations that initiate a request to which a user can respond. Example: Netflix prompts users "Are you still watching"?
- Deciding which interaction type to use can help designers formulate a conceptual model
  - Instructing: Users issue instructions to a system
  - Conversing: Users have dialog with a system
  - Manipulating: Users interact with objects
  - Exploring: Users move through space
  - Responding: System initiates the interatcion and user chooses whether to response
- Instructing
  - Describes how users carry out tasks by telling system what to do
    - Give instructions to a system: Print, "Remind", "Count". Issueing commands
    - Interaction should be quick and efficient
- Conversing
  - System acts as a dialogue partner
  - 2-way communication process
  - Used for apps where user needs to find out specific types of info or discuss issues
  - Allows people to interact with a system in a way that is familiar to them.
  - ! Danger: Some tasks can be transformed into cumbersome, one-sided interactions

- Manipulating
  - Capitalize on user's knowledge of how they interact with things in the physical world
    - Moving, selecting, opening closing: Zooming, stretching, shrinking
    - Direct manipulation: Users should feel they are directly controlling digital objects
      - Continuous representation of objects
      - Rapid reversible incremental actions with immediate feedback
      - Physical actions and button pressing instead of issuing commands
    - Drawbackas: Not all tasks can be described by objects, and not all actions can be taken directly

- Exploring
  - Moving through virtual or physical environments, using people's knowledge of how they move through space

- Responding
  - System taking initative to alert, describe or show user things
  - ! Drawback: System initiated interactions might get tiresome or frustrating, especially if system gets it wrong.
  - Must know what user will find useful and interesting and how much/wht kind of info to provide without annoying them. Also- what to do when it gets things wrong?

## 3.6 - Paradigms, Visions, Theories, Models, Frameworks

- Paradigms: Adopt a set of practices upon which a community has agreed
  - Includes: - Questions to be asked, how to be framed - Phenomena to be observed - Ways in which findings are to analyzed/interpreted

- Visions: SCI-FI source of inspiration. Provide concrete scenarios of how society can use the next gen of imagined technologies

- Theories: Means of anlayzing and predicting the performance of users carrying out takss

- Models: Depicts how core features are structured and related to each other. Ex: Don norman made models based on theorieies of cognitive processing. USer models

- Frameworks: Frameworks help designers constrain and scope the UX for which they are designing. DiCOT: Analyze qualitative data at a system level. Don Norman's framework: 3 parts: Designer's Model, System Image, User's Model
